# Ядро управления станком

Текст для программиста, который будет вызывать это ядро из своей программы.
Сборщику станка достаточно раздела «Что должно быть уже сделано на станке».

## Что это

Ядро — обычный класс на Python. Оно стоит на Raspberry Pi и по USB говорит с
Arduino Mega. На Mega крутится прошивка grbl-Mega-5X. Прошивка сама выдаёт
импульсы STEP/DIR на драйверы DM542. Ядро импульсы не генерирует.

```
ваша программа
    ↓  cnc.hold("X", +1)  /  cnc.jog_step(...)  /  cnc.run_program(...)
GrblCore
    ↓  serial 115200, порт обычно /dev/ttyACM0
Arduino Mega + grbl-Mega-5X
    ↓  STEP / DIR
DM542 → шаговые моторы
```

Оси по умолчанию:

| Буква | Что это        | Единицы |
|-------|----------------|---------|
| X Y Z | головка, ШВП   | мм      |
| A     | поворот стола  | градусы |

Помпа — не ось. Это отдельный выход «вкл/выкл».

Позже, на плате PiBot, протокол тот же. В конструкторе меняется только порт.
Методы трогать не нужно.

## Чего ядро не умеет

- Не выставляет ток и микрошаг DM542. Это переключатели на корпусе драйвера.
- Не заменяет прошивку. Без grbl-Mega-5X на Mega класс бесполезен.
- Не рисует интерфейс. Кнопки, окно, джойстик — ваша программа.
  `examples/keyboard_jog.py` — готовый пример, как это выглядит.
- Не знает ваш винт, редуктор и ток, пока их не впишут в `grbl_core/machine_config.py`.
  После этого ядро само считает импульсы на миллиметр и на градус.

## Установка

Папка `cnc_core` должна лежать на Raspberry Pi. Из вашей программы:

```python
import sys
sys.path.insert(0, "/home/pi/cnc_core")  # путь, куда положили папку

from grbl_core import GrblCore
```

Или из этой папки: `pip3 install .`

Нужен пакет `pyserial`. Для примера с клавиатурой ещё `pynput`.
Пользователь Pi должен быть в группе `dialout`, иначе порт не откроется.
После добавления в группу нужен новый вход в систему.

Проверка без станка и без Arduino:

```bash
python3 examples/keyboard_jog.py --simulate --demo
```

В ответе будет строка `MPos`. Это симулятор, моторы не едут.

## Числа станка: файл machine_config.py

Это единственный файл под конкретный станок. Путь: `grbl_core/machine_config.py`.
Ядро, тестовый пульт и чужая программа читают его сами. В `core.py` эти числа
не ищут и не правят.

В файле уже стоят рабочие значения по умолчанию. Пока они не совпали с железом,
меняют строку в файле и сохраняют. Перезапуск программы подхватывает новое.
Отдельно «загружать конфиг» не нужно.

Посмотреть, во что файл превратился, без станка и без Mega:

```bash
python3 -m grbl_core.machine_config
```

Будет строка на каждую ось: сколько импульсов на мм, какой шаг jog и какая подача.
Для винта 5 мм и микрошага 8 это 320 импульсов на мм. Для стола без редуктора
при тех же 200 шагах и микрошаге 8 это 4.4444 импульса на градус.

После `connect()` файл записывается в память Mega одной командой:

```python
cnc.apply_machine()
```

Туда уходят импульс STEP, инверсия направлений, шаги, потолок скорости, разгон
и ход. Ток драйвера не уходит: его ставят рычажками на корпусе DM542.
`CURRENT_A` в файле только для того, чтобы сборщик и программа называли одно
и то же число.

Пока ось уже едет, шаг и подачу можно менять методами `set_step` и `set_feed`.
Файл для этого не открывают. Эти методы живут до закрытия программы.
Чтобы новое число осталось и после перезапуска, его пишут в `machine_config.py`.

### Связь

| Строка | По умолчанию | Зачем |
|---|---|---|
| `PORT` | `/dev/ttyACM0` | USB-порт Mega на Raspberry Pi. Если плата села как `ttyUSB0`, меняют здесь |
| `BAUD` | `115200` | Скорость. Такая же, как в `config.h` прошивки. Не менять |
| `POLL_INTERVAL` | `0.08` | Как часто спрашивать координаты, в секундах. На движение не влияет |

### Драйвер, общее на все оси

| Строка | По умолчанию | Зачем |
|---|---|---|
| `CURRENT_A` | `2.37` | Какой ток выставлен рычажками SW1–SW3. В плату не пишется |
| `MICROSTEP` | `8` | Микрошаг, если у конкретной оси не написан свой |
| `MOTOR_FULL_STEPS` | `200` | Полных шагов мотора на оборот. 200 — это обычный мотор 1.8° |
| `PULSE_US` | `10` | Длительность импульса STEP в микросекундах, попадает в `$0`. Даташит DM542 принимает от 2.5, десять устойчивее на длинном проводе |
| `BENCH_MODE` | `True` | Нет концевиков. `apply_machine()` выключит homing и мягкие лимиты. Когда датчики появятся, поставить `False` |

Допустимый микрошаг DM542: 2, 4, 8, 16, 32, 64, 128, 5, 10, 20, 25, 40, 50, 100, 125.
Допустимый пиковый ток: 1.00, 1.46, 1.91, 2.37, 2.84, 3.31, 3.76, 4.20 ампера.
Рычажки печатает сам файл, если его запустить командой выше.

### Каждая ось в словаре AXES

Буквы фиксированы: X, Y, Z — винты головки, A — поворотный стол.
У каждой одни и те же поля.

| Поле | Что писать | Куда попадает |
|---|---|---|
| `kind` | `"linear"` для винта, `"rotary"` для стола | никуда, только чтобы формула знала, мм это или градусы |
| `pitch_mm` | шаг винта, мм за один оборот. Надпись на гайке ШВП, например 5 или 10. У стола можно оставить 0 | из него считаются импульсы на мм |
| `gear_ratio` | сколько оборотов мотора на один оборот винта или стола. Прямая муфта = 1. Редуктор 90:1 = 90 | туда же |
| `microstep` | как стоят SW5–SW8 на этом драйвере | туда же |
| `motor_full_steps` | почти всегда 200 | туда же |
| `step` | сколько мм или градусов проехать за один вызов `jog_step` | только ядро, в EEPROM не пишется |
| `feed` | скорость ручного хода, мм/мин или градус/мин | только ядро, пока не упрётся в потолок |
| `max_feed` | выше этой скорости `set_feed` не пустит | `$110`…`$113` |
| `accel` | разгон | `$120`…`$123` |
| `continuous_window` | длина куска, пока кнопка зажата. Меньше — чаще обновляется скорость, больше — ровнее едет | только ядро |
| `max_travel` | мягкая граница в плюс. 0 = границы нет | `$130`…`$133`, ноль в плату не пишется |
| `min_pos` | мягкая граница в минус | только ядро |
| `invert` | `True`, если ось поехала не в ту сторону | бит в `$3`. Провода не перекидывать |

Формула, чтобы было понятно, откуда 320:

```
импульсов на мм = 200 * микрошаг * gear_ratio / pitch_mm
импульсов на градус = 200 * микрошаг * gear_ratio / 360
```

Пример. Винт 1610 (ход 10 мм), микрошаг 8, муфта прямая:

```python
"pitch_mm": 10.0,
"microstep": 8,
"gear_ratio": 1.0,
```

Это 160 импульсов на мм. Считать руками не нужно.

Стол с червяком 90:1:

```python
"kind": "rotary",
"gear_ratio": 90.0,
```

`pitch_mm` у стола не используется.

Сейчас в файле по умолчанию:

| Ось | Винт / редуктор | Шаг jog | Подача | Потолок | Кусок удержания |
|---|---|---|---|---|---|
| X, Y | 5 мм, редуктора нет | 1 мм | 1200 мм/мин | 3000 | 25 мм |
| Z | 5 мм, редуктора нет | 0.5 мм | 600 мм/мин | 1500 | 10 мм |
| A | стол, редуктор 1:1 | 1° | 900 °/мин | 2000 | 20° |

Потолок 3000 — осторожный, не максимальный для драйвера. Поднимать после того,
как ось уже поехала в нужную сторону.

### Помпа

В шкафу сверху стоит клапан и отдельный чёрный узел. Это не пятый DM542.
Пока не ясно, какой пин Mega их включает, в файле оставлено:

```python
PUMP_MODE = "digital"   # выход вкл/выкл, команда M64/M65
PUMP_INDEX = 0          # 0 = пин D16, 1 = D17, 2 = D23, 3 = D25
PUMP_AXIS = "B"         # используется, только если PUMP_MODE = "axis"
```

`"coolant"` — если выход сидит на охлаждении, команды M8/M9.
`"axis"` — если помпа вдруг тоже шаговый драйвер.
Пока помпу с клавиатуры не нажимать: провода на фото к D16 не проверены.

### Переменные окружения

Любое число из файла можно перекрыть, не редактируя файл. Имя написано
комментарием справа. Пустая переменная не считается.

```bash
export CNC_PORT=/dev/ttyUSB0
export CNC_X_PITCH=10
export CNC_A_GEAR=90
export CNC_X_INVERT=1
export CNC_BENCH=1
```

Для полей оси шаблон такой: `CNC_` + буква + `_` + имя.
Буква X, Y, Z или A. Имена: `PITCH`, `GEAR`, `MICROSTEP`, `MOTOR_STEPS`,
`STEP`, `FEED`, `MAX_FEED`, `ACCEL`, `WINDOW`, `MAX_TRAVEL`, `MIN_POS`, `INVERT`.
Общие: `CNC_PORT`, `CNC_BAUD`, `CNC_POLL_S`, `CNC_CURRENT_A`, `CNC_MICROSTEP`,
`CNC_MOTOR_STEPS`, `CNC_PULSE_US`, `CNC_BENCH`, `CNC_PUMP_MODE`, `CNC_PUMP_INDEX`,
`CNC_PUMP_AXIS`.

## Первые строки в вашей программе

```python
from grbl_core import GrblCore

cnc = GrblCore()          # порт и оси уже взяты из machine_config.py
cnc.on_log = print
cnc.connect()
cnc.apply_machine()       # записать шаги, скорости, импульс и инверсии в Mega

cnc.set_step("X", 0.2)    # на лету, в файл это писать не обязательно
cnc.set_feed("Y", 2400)
cnc.jog_step("X", +1)

cnc.close()
```

`connect()` сам снимает блокировку (`$X`). Повторный `connect()` без `close()`
бросает ошибку. Удобная форма:

```python
with GrblCore("/dev/ttyACM0") as cnc:
    cnc.bench_mode()
    ...
```

## Два способа двигать ось

### Один шаг

`jog_step` сдвигает ось на расстояние `step` с подачей `feed`.
Знак: `+1` в плюс, `-1` в минус.

```python
cnc.set_step("X", 0.2)     # 0.2 мм за один вызов
cnc.set_feed("X", 1500)    # 1500 мм/мин
cnc.jog_step("X", +1)
cnc.jog_step("Z", -1)
```

Шаг не обязан быть равен одному микрошагу двигателя. Это просто «на сколько
сдвинуть по команде». Хотите 10 мм за раз — поставьте `set_step("X", 10)`.

Пока зажато непрерывное движение, `jog_step` откажется. Сначала `release`.

### Удержание, как кнопка пульта

Ось едет, пока вы её не отпустите. Отпускание останавливает почти сразу,
не дожидаясь конца заказанного куска.

```python
cnc.hold("Y", +1)     # поехали в плюс
cnc.hold("X", -1)     # одновременно ещё и X, вектор
cnc.release("X")      # X встал, Y продолжает
cnc.release("Y")      # всё встало
cnc.stop()            # то же, что отпустить все оси
```

Повторный `hold` с тем же знаком ничего не делает. Это защита от автоповтора
клавиатуры: кнопка может слать «нажато» десять раз в секунду, а ось не должна
от этого дёргаться.

Как это устроено внутри. Пока кнопка зажата, ядро само подкладывает короткие
команды `$J=G91 …`. Длина одного куска — поле `continuous_window`
(у X/Y это 25 мм, у Z 10 мм, у A 20 градусов). Когда кнопку отпустили, в порт
уходит один байт отмены jog, не новая строка программы. Контроллер бросает
остаток куска и тормозит.

Скорость удержания — тот же `feed`, что и у шага. Поменять её можно в полёте:

```python
cnc.hold("Y", +1)
cnc.set_feed("Y", 2400)   # текущий кусок оборвётся и продолжится уже быстрее
```

`scale_steps(2)` удваивает шаг всех осей. `scale_steps(0.5)` уменьшает вдвое.
`scale_feeds` делает то же с подачей, но не выше `max_feed` каждой оси.
Ниже 0.001 мм шаг не уйдёт, ниже 1 мм/мин подача тоже.

Несколько осей сразу едут с подачей самой медленной из зажатых.
Так ни одна не превысит свою скорость.

## Две разные «скорости», их путают

| Что вызвать | Где живёт | Смысл |
|---|---|---|
| `set_feed` | только в ядре | с какой скоростью ехать сейчас, в jog |
| `set_max_feed(..., to_grbl=True)` | в ядре и в памяти Mega | потолок. Выше него jog не разгонится |

`set_feed("X", 5000)` при `max_feed` 2000 бросит `ValueError`.
Сначала поднимите потолок, если механика это позволяет:

```python
cnc.set_max_feed("X", 4000, to_grbl=True)
cnc.set_feed("X", 3500)
```

Подача в градусах для стола — те же методы, единица уже «градус в минуту».

## Что можно менять на лету

Всё из этого читается в момент отправки команды, отдельные потоки не мешают друг другу:

```python
cnc.configure(
    "Z",
    step=0.05,
    feed=400,
    max_feed=800,
    accel=80,                 # мм/с², уходит в контроллер только с to_grbl=True
    continuous_window=5,      # длина куска при удержании
    max_travel=180,           # мягкая граница в плюс, 0 = не ограничивать
    min_pos=0,                # мягкая граница в минус
    steps_per_unit=320,
    unit="mm",
    to_grbl=False,
)
```

`max_travel` ядра — это не концевик. Ядро просто не закажет кусок, который
вылезает за границу, если уже знает координату. Ноль означает «границы нет».
Пока координата с платы не пришла, ограничение не применяется.

Запись в память Mega (сохранится после выключения питания):

```python
cnc.push_axis("X")
```

Туда уходят, если значение ненулевое:

| Поле оси | Номер GRBL | Что это |
|---|---|---|
| steps_per_unit | $100 X, $101 Y, $102 Z, $103 A | импульсов на мм или на градус |
| max_feed | $110…$113 | максимальная скорость |
| accel | $120…$123 | разгон |
| max_travel | $130…$133 | ход оси в самом GRBL |

`set_steps_per_unit` пишет в контроллер сразу. Если писать не надо
(нет связи или хотите только посчитать) — `to_grbl=False`.

Любой другой параметр GRBL:

```python
cnc.set_grbl(3, 1)          # пример: инвертировать направление X
cnc.refresh_settings()      # прочитать все $ с платы
```

`bench_mode()` выключает мягкие лимиты, концевики и homing (`$20 $21 $22 = 0`)
и снимает блокировку. Вызывайте только на станке без датчиков.
Когда концевики появятся, этот метод больше не вызывать.

`apply_dm542_timing()` ставит `$0 = 10` (длительность импульса, микросекунды).
Драйвер принимает от 2.5. Десять устойчивее на длинном проводе.

`driver_warnings()` вернёт список строк, если при текущих шагах и `max_feed`
частота импульсов выше 200 кГц. Это потолок DM542. Лечится меньшим микрошагом
на DIP или меньшим `max_feed`. Пустой список — упираться не во что.

Формулы и подписи DIP, если нужно показать их оператору:

```python
from grbl_core import describe_microstep, describe_current

describe_microstep(8)     # какие SW5…SW8 включить
describe_current(2.37)    # какие SW1…SW3
```

Допустимые микрошаги DM542: 2, 4, 8, 16, 32, 64, 128, 5, 10, 20, 25, 40, 50, 100, 125.
Ток, пиковые амперы: 1.00, 1.46, 1.91, 2.37, 2.84, 3.31, 3.76, 4.20.

`ballscrew_steps_per_mm(шаг_винта_мм, microstep=8, motor_full_steps=200, gear_ratio=1)`
`gear_ratio` — сколько оборотов мотора на один оборот винта. Редуктора нет, значит 1.

`rotary_steps_per_deg(microstep=8, motor_full_steps=200, gear_ratio=90)`
здесь `gear_ratio` — сколько оборотов мотора на один оборот стола.

## Где станок сейчас

```python
status = cnc.refresh_status()   # подождать свежий ответ, либо GrblError
# status = cnc.get_status()     # последнее уже полученное, может быть None
```

У ответа есть:

| Поле | Смысл |
|---|---|
| `state` | `Idle`, `Jog`, `Run`, `Hold`, `Alarm`, `Home`, `Door` |
| `mpos` | словарь координат станка, мм или градусы: `{"X": 1.2, "Y": 0, ...}` |
| `wpos` | рабочая координата, если плата её прислала |
| `feed` | фактическая подача из статусной строки |
| `raw` | строка как пришла с платы |
| `t` | время получения, `time.time()` |

Постоянно координаты приходят сами, около 12 раз в секунду.
Свой обработчик:

```python
def on_status(status):
    x = status.mpos.get("X", 0)

cnc.on_status = on_status
cnc.on_alarm = print
cnc.on_log = print
```

Обработчик вызывается из отдельного потока. Не запускайте из него
`run_program` и не делайте долгих операций. Сохранить цифру в переменную — можно.
Методы `hold`, `release`, `set_feed`, `jog_step` из другого потока вызывать можно.

## Программа G-code

```python
sent = cnc.run_program("""
G21
G90
G0 X10 Y0
G1 X10 Y20 F800
""")
```

Строки уходят по одной. Ядро ждёт `ok` на каждую. Комментарии в скобках и после
`;` выбрасываются. Возвращается число реально отправленных строк.
Пока какая-то ось зажата через `hold`, программа не стартует.

```python
cnc.abort_program()  # не слать следующие строки и поставить паузу (!)
cnc.resume()         # снять паузу (~)
```

Важная тонкость. `abort_program` не выдёргивает уже ушедшую длинную строку из
`run_program`: тот вызов сидит и ждёт `ok`, а пауза как раз не даёт этот `ok`,
пока не будет `resume()`. Для кнопки «стоп» на ручном ходу используйте `stop()`,
не `abort_program`.

Полный обрыв всего, включая текущее движение:

```python
cnc.reset()    # как ctrl-x на плате
cnc.unlock()   # снова разрешить движение
```

Свои команды, если готового метода нет:

```python
cnc.command("G90")
cnc.command("G0 X0 Y0", timeout=30)
cnc.home()     # $H, имеет смысл только с концевиками, ждёт до 120 с
```

`command` бросает `GrblError`, если ответ не `ok`.

## Помпа

Пока неясно, реле это или ещё один шаговый драйвер. Три режима:

```python
cnc.pump_mode = "digital"   # по умолчанию: M64/M65, сразу, не дожидаясь кадра
cnc.pump_index = 0          # 0 → пин D16, 1 → D17, 2 → D23, 3 → D25
cnc.set_pump(True)
cnc.set_pump(False)

cnc.pump_mode = "coolant"   # M8 / M9, если выход помпы сидит на coolant
cnc.pump_mode = "axis"      # помпа тоже шаговик
cnc.pump_axis = "B"         # STEP D36, DIR D34
```

`cnc.pump_is_on` — последнее, что просили, а не датчик с платы.

## Ошибки

`GrblError` — плата отказала, нет связи, таймаут, нет такой оси, jog во время
удержания, программа во время удержания.

`ValueError` — в метод передали ноль, отрицательное или подачу выше потолка.

Нет порта:

```text
GrblError: не открылся /dev/ttyACM0
```

Смотреть `ls /dev/ttyACM* /dev/ttyUSB*` и группу `dialout`.

После аварии платы (`Alarm`) движение не поедет, пока не будет `unlock()`.
`connect()` делает это сам один раз.

## Потоки внутри

Их четыре, все служебные. Свои потоки заводить не нужно, но можно:
методы ядра можно звать из разных потоков.

| Поток | Зачем |
|---|---|
| grbl-reader | читает ответы платы |
| grbl-status | спрашивает координаты, движение от этого не встаёт |
| grbl-callbacks | ваши `on_status` / `on_alarm` |
| grbl-jog | пока ось зажата, подкладывает куски и снимает их по `release` |

Частоту опроса координат меняют до `connect()`:

```python
cnc = GrblCore("/dev/ttyACM0", poll_interval=0.05)  # секунды
```

## Пример с клавиатуры

Это не часть ядра, а образец клиента: `examples/keyboard_jog.py`.

```bash
python3 examples/keyboard_jog.py --port /dev/ttyACM0
```

| Клавиша | Действие |
|---|---|
| W / S | Y+ / Y− |
| A / D | X− / X+ |
| Q / E | Z+ / Z− |
| R / F | стол A+ / A− |
| пробел | стоп |
| P | помпа |
| , / . | шаг всех осей ÷2 / ×2 |
| − / = | подача всех осей ÷2 / ×2 |
| 1 | режим одного шага |
| 2 | режим удержания |
| Esc | выход |

По умолчанию удержание: ось едет, только пока клавиша нажата.
Шаг, подача и потолок берутся из `machine_config.py`, не из этого примера.

## Что должно быть уже сделано на станке

Прошивка — grbl-Mega-5X, не обычный GRBL из менеджера библиотек.
В `libraries/grbl/config.h` меняется одна строка:

```c
#define N_AXIS 4
```

Рядом остаётся `#define N_AXIS_LINEAR 3`. Имена осей не трогать: X, Y, Z и A.
Не трогать и эти две строки, они уже правильные:

```c
#define BAUD_RATE 115200
#define CPU_MAP_2560_RAMPS_BOARD
```

После заливки один раз отправить `$RST=*`, затем `$X`.

Пины, которые прошивка считает STEP и DIR. На красном клеммнике Mega
они подписаны так же.

| Ось | STEP | DIR | ENABLE не подключать |
|---|---|---|---|
| X | A0 | A1 | D38 |
| Y | A6 | A7 | A2 |
| Z | D46 | D48 | A8 |
| A | D26 | D28 | D24 |

Шкаф на фото уже собран: четыре чёрных DM542, питание снизу от блока,
обмотки моторов уходят жгутом справа, сигналы приходят тонкими проводами
с красной платы слева. Эти провода не перетыкать, пока не сверено, какой
цвет сидит на каком винте клеммника. Красные перемычки на сигнальных клеммах
драйвера — общий плюс, так и оставлять. Если ось поедет не туда, в
`machine_config.py` у неё ставится `"invert": True`.

Клапан и чёрный узел сверху — не шаговый драйвер. К STEP/DIR их не сажать.
